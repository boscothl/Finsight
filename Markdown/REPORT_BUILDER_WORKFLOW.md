# Finsight Report Builder Workflow

This document details the user journey and backend technical workflows for the Finsight Report Builder module, covering both **Simple Mode** and **Advance Mode**, as well as the **Style Management** pipeline.

---

## 1. Backend Conceptual Core: The "Two-Agent" Data Pipeline

Regardless of whether a user requests a report via the Simple Form or the Advance Chatbot, the backend execution relies on a secure, two-step AI pipeline to protect the application's database from malicious code execution.

1. **Step 1: Data Intent Agent (Gemini 2.5 Pro)**
   * **Input:** A natural language request (or a structured string combined from a form).
   * **Task:** Extract the user's intent to determine *exactly* what database records are required (e.g., date ranges, claim statuses, specific budget pools). 
   * **Output:** A strict JSON structure mapping the required query parameters.
   * **System Action:** Django intercepts this JSON, securely queries the PostgreSQL database via standard ORM (`Claim.objects.filter(...)`), and serializes the result into a sanitised JSON array (The "Data Payload").

2. **Step 2: Code Generation Agent (Gemini 2.5 Pro)**
   * **Input:** The required format (XLSX, DOCX, PPTX), the extracted Style JSON, and the sanitised **Data Payload**.
   * **Task:** Generate a standalone, production-ready Python script using libraries like `openpyxl`, `python-docx`, or `python-pptx` to construct the final document and populate it recursively using the provided data limit.
   * **System Action:** The system takes the raw python code, executes it inside an isolated namespace (`exec()` locally, or an isolated Cloud Run container in production), generating the final `.xlsx/.docx/.pptx` file.

## 2. Style Management: Extraction & Injection

The Style Manager extract style of documents strictly on **PDFs and Images (JPG/PNG)**.

**Extraction Workflow:**
1. **User Upload:** User opens the "Manage Styles" modal and drops a reference PDF or Image.
2. **AI Multimodal Scan:** The backend converts the upload into binary data and passes it to Gemini 2.5 Pro using `Part.from_data(..., mime_type="application/pdf")`.
3. **JSON Structure:** The model analyzes the pixels for visual design cues and is prompted to return a strict JSON payload containing:
   * **Color Palette & Accents:** Hex codes for Primary, Secondary, Background, and Text, as well as rules for when to apply them (e.g., "Use Primary Color for table headers, and alternating light gray for row backgrounds").
   * **Typography & Hierarchy:** Font families (e.g., Arial, Calibri) alongside sizing weights for titles, subtitles, and body text.
   * **Layout & Structure:** Structural requirements such as "Centered titles", "borderless tables", "generous padding between sections", or "landscape orientation".
   * **Vibe/Description:** A succinct prompt-friendly summary generated by the AI (e.g., "A clean, modern corporate theme with navy blue headers, sans-serif fonts, and minimalist borders").
4. **Save to DB:** The structured JSON is saved in the database as a reusable Theme (e.g., "Corporate Standard").

**Injection Workflow:**
When generating a report, if a saved Style is selected, the JSON is injected into the **Code Generation Agent's System Prompt**, instructing it to apply specific hex codes via `PatternFill` (Excel) or specific paragraph alignments (Word).

## 3. Workflow: Simple Mode (Form-Based)

Simple mode acts as a UI wrapper that synthesizes standard dropdown selections into a robust prompt for the backend.

1. **UI Selection:** The user fills out discrete fields:
   * Time Period (e.g., "Last 30 Days")
   * Report Type (e.g., "Expense Analysis")
   * Format ("xlsx")
   * Style ("Corporate Theme")
2. **Prompt Synthesis (Backend):** Django combines these into a string: *"Generate an Expense Analysis for the Last 30 Days in XLSX format."*
3. **Execution:** 
   * Passed to **Agent 1** -> JSON intent -> Django fetches Last 30 Days of Claims.
   * Django pulls the "Corporate Theme" JSON from the DB.
   * Passed to **Agent 2** (with Data + Style) -> Python Script Generated -> Executed.
4. **Resolution:** The user is immediately redirected to the `/reports/` Library view where their newly generated file is ready for download.

---

## 4. Workflow: Advance Mode (Iterative Chat)

Advance Mode offers a conversational, exploratory interface.

1. **User Interaction:** The user converses naturally: *"Can you break down Q3 travel expenses and highlight anything over $1000 in red?"*
2. **Context Persistence:** Django tracks the chat session, so the agent remembers previous steps.
3. **Execution Loop:**
   * **Agent 1** recognizes the need for "Q3 Travel Claims". Django runs the query.
   * **Agent 2** generates the python code with the conditional logic ("highlight > $1000 in red").
   * The script executes, creating the file.
4. **Agent Response:** The chat interface receives the generated file path. The Bot responds: *"I've generated the Q3 Travel summary. [Download Link]"*
5. **Style Capture (Iterative UI):** If the user later says, *"Make the headers blue and use Times New Roman"*, the bot regenerates the document. Finsight recognizes the bot manipulated styling, and dynamically injects a **"Save Extracted Style"** snippet/button into the chat feed, allowing the user to persist this new style setting into the database permanently.

## 5. Specific Use Cases and Interaction Flows

### Case A: The "Quick Month-End" (Simple Mode)
* **Objective:** The Finance Manager just needs their standard end-of-month Excel dump.
* **Flow:**
  1. Opens `/chatbot/`. Tab defaults to Simple Mode.
  2. Selects "Last 30 Days", "Financial Summary", "XLSX", and "Corporate Theme" from dropdowns.
  3. Clicks "Generate".
  4. The Two-Agent pipeline spins up synchronously. No conversation is needed.
  5. User is redirected to `/reports/` where the fresh Excel file is waiting.

### Case B: The "Messy Exploration" (Advance Mode)
* **Objective:** The admin needs to investigate an anomaly and wants a highly custom presentation.
* **Flow:**
  1. Switches to Advance Mode.
  2. User: *"Give me a PowerPoint showing a bar chart of all software subscriptions purchased this year."*
  3. Pipeline executes. The Chatbot returns a PPTX link inline in the chat.
  4. User views it, realizes it's missing context, and replies: *"Actually, group these by user and put it in a Word document table instead."*
  5. Django passes this new intent (with Chat History). Agent 2 switches the library from `python-pptx` to `python-docx` using the same underlying DB payload. Chatbot returns the new DOCX link.

### Case C: The "Brand Update" (Style Extraction)
* **Objective:** The company changed its logo and branding, and wants all Finsight reports to match the new company letterhead.
* **Flow:**
  1. Admin opens `/chatbot/` (Simple Mode) and clicks "Manage Styles".
  2. Modal opens. Admin drops the newly designed company letterhead (`letterhead_2026.pdf`) into the dropzone.
  3. Finsight pushes the PDF to Gemini. Gemini parses the visual design and returns a standard Finsight Style JSON.
  4. The DB saves this as "New Brand 2026".
  5. The next time the admin generates a report (in Simple or Advance mode), they select "New Brand 2026" and Agent 2 automatically receives the new Hex Codes to apply to the python generation script.
